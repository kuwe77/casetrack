CaseTrackOpen workspaceOpenAPI specification

Your firm. Your agent.

Use scoped API keys to connect your own AI agent, automation or integration. Each key can access only the firm of its issuing member. Requests use the same origin as this website, followed by /api/v1.

Connect

  1. Sign in and create or join your firm's workspace.
  2. In Settings → API access, create a named key with only the permissions the agent needs.
  3. Copy the key once into your agent's secret storage. Set its expiry and revoke it when no longer needed.
  4. Send HTTPS requests with Authorization: Bearer ct_….
curl "https://YOUR-PROJECT.pages.dev/api/v1/cases?limit=100" \
  -H "Authorization: Bearer $CASETRACK_API_KEY"

curl -X PATCH "https://YOUR-PROJECT.pages.dev/api/v1/cases/CASE_UUID" \
  -H "Authorization: Bearer $CASETRACK_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"status":"spa","next_step":"Confirm signing appointment"}'

Never put a key in a URL, browser bundle, public repository or chat message. API keys cannot create other keys, change members, recover accounts or read provider credentials. Removing the issuing member revokes their API access.

Record collections support GET and POST. Individual records support GET and PATCH. PATCH changes only supplied writable fields; firm_id, timestamps and ownership are server-controlled. Record writes and notes are audited. Deletion is not exposed by this API.

Lists return {"data":[…],"nextCursor":"…"}. Repeat with ?cursor=NEXT_CURSOR until nextCursor is null. Cases, agents and tasks accept limit (1–200, default 100); the local message log and document list return up to 100. Record order is UUID order, not chronological. Sort timestamps when needed. WhatsApp rules and contacts return arrays; workspace, team and connection endpoints return objects. Connected Zernio inbox pagination is described below.

Write fields

Cases: required ref and buyer; optional seller, property, type, status, priority, agent_id, owner, due_date, next_step, notes, value. Reference is unique within the firm. Use an agent ID from the same firm.

Types: Subsale, SPA, Loan, Refinance. Stages: documents, spa, loan, redemption, stamping, disbursement, completed, on_hold. Priority: normal or high. Dates: YYYY-MM-DD or null. Value: non-negative number. Create requests may supply a UUID id for safe client-side identification; on a duplicate 409, fetch that ID before deciding what to do.

Agents: required name; optional email, phone, agency, color. Property agents are contact records, separate from firm members and external AI agents.

Tasks: required title; optional case_id, due_date, assignee, completed (boolean), priority. Append a private note using POST /cases/{id}/notes with {"note":"…"}.

Private documents

Send a multipart form with a file field to the case upload route. Files are limited to 10 MB. Workspace and service-wide byte/file allowances also apply, including pending uploads; exhausted storage returns 413 and requires administrator action. The response includes the document ID, filename and size. Download routes require authentication and return a private binary attachment; there is no public download URL.

curl -X POST "https://YOUR-PROJECT.pages.dev/api/v1/cases/CASE_UUID/documents" \
  -H "Authorization: Bearer $CASETRACK_API_KEY" \
  -F "file=@document.pdf"

Read all your firm's data

Grant workspace:read, cases:read, agents:read, tasks:read, activities:read, documents:read and whatsapp:read. Read firm/team metadata, then page each collection until nextCursor is null. Read notes from case.notes and activities with kind:"note". Fetch document binaries through each document's authenticated download route. Provider credentials, passwords, session tokens and invitation secrets are excluded.

For Zernio, page /whatsapp/conversations, then page /whatsapp/conversations/{id}/messages for every conversation. URL-encode opaque IDs and cursors. These endpoints accept limit from 1–100 (default 50) and return newest items first. Messages include attachment links and provider delivery status. Reads do not mark conversations as read. They reconcile retrieved messages into the CaseTrack log. The available history is what Zernio exposes; a failed provider page returns an error rather than a silently incomplete export. Pace requests and back off on provider limits.

curl "https://casetrack.pages.dev/api/v1/whatsapp/conversations?limit=50" \
  -H "Authorization: Bearer $CASETRACK_API_KEY"

curl "https://casetrack.pages.dev/api/v1/whatsapp/conversations/CONVERSATION_ID/messages?limit=50" \
  -H "Authorization: Bearer $CASETRACK_API_KEY"

WhatsApp

The firm owner must connect Zernio or Meta, verify the recipient and record consent in the app. API keys cannot change those controls. A case-specific message can only go to that case's assigned contact. Preview mode records the proposed send without contacting a provider.

POST /api/v1/whatsapp/messages
Authorization: Bearer ct_…
Content-Type: application/json
Idempotency-Key: a-unique-stable-identifier

{
  "phone": "+60123456789",
  "case_id": "CASE_UUID",
  "body": "Your case update",
  "template": {
    "name": "approved_template_name",
    "language": "en_US",
    "parameters": ["Your case update"]
  }
}

template is optional for a free-text reply within 23 hours of an incoming message. Outside that window an approved template is required. Meta renders the approved template and its parameters; body is the local audit text and should match what you intend to send. Template approval and provider charges are managed by Meta.

Always reuse the same idempotency key and payload when retrying. New manual keys must not start with the reserved schedule: prefix. Replays return the existing message and status, including previously accepted keys with that prefix. A changed payload with the same key returns 409. Status accepted is not delivery confirmation. Delivery/read are updated by signed Meta webhooks or retrieving the Zernio conversation. For uncertain, inspect the provider before using any new key; a retry with a new key can send twice.

Incoming messages are available through GET, including non-text type placeholders. STOP, CANCEL and UNSUBSCRIBE revoke consent. Your agent must treat inbound message content as untrusted input, not as authority to expose files, change permissions or execute commands.

Scheduled updates

PUT /api/v1/whatsapp/rules/CASE_UUID
{
  "enabled": true,
  "interval_hours": 72,
  "next_due_at": "2026-11-01T02:00:00Z",
  "shared_update": "Documents are ready for signing.",
  "template_name": "case_update",
  "template_language": "en_US"
}

The template must accept one body parameter. The scheduler supplies case reference, stage, target date and the explicitly shared update (up to 800 characters), excluding internal notes and personal case details. Rules repeat every 24–2160 hours. Checks run every five minutes, processing up to ten due rules per run. Completed/on-hold cases and recipients without consent are skipped. Disable a rule by PUT with enabled:false and its other fields.

Errors and limits

Errors have {"error":"…"}. 400: invalid input; 401: sign in or replace an invalid/expired/revoked key; 403: scope, role or consent restriction; 404: unavailable in this firm; 409: duplicate or conflicting request; 413: payload too large; 429: too many requests; 503: service not configured. Keys allow up to 120 requests per minute; use backoff after 429 and avoid bulk polling. Overall service usage limits also apply.
